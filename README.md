# Tabi Stickers

(Repo, npm package and Expo slug are still `lingostickers-mobile`; the public
app name is **Tabi Stickers**, bundle id `com.iancheung228.lingostickers`. Test
builds are **Tabi Dev** (`.dev`) and **Tabi Preview** (`.preview`), on a
separate staging backend: see [RELEASING.md](./RELEASING.md).)

Tabi Stickers is an iOS-first language-learning app built around your own
photos. Point the camera at a real object (or import a photo), outline the
thing you mean, and the app cuts it out on-device as a sticker and has an LLM
produce a flashcard: the word in the target language, how to say it, its
meaning, a sentence about the scene, and a grammar note. Cards can also be made
from a typed word or from "scene prompts" (extra words/idioms suggested from
the same photo). Cards are reviewed with a spaced-repetition scheduler (SM-2
with minute-granular learning steps), arranged on boards and a home wall, and
kept in a calendar of when they were found. Target languages: French (`fr`),
Japanese (`ja`) and Cantonese (`yue`) — see `lib/types.ts`. Friends and
challenges are built but switched off for the v1 release
(`SOCIAL_ENABLED = false` in `lib/features.ts`).

Product direction and status: [ROADMAP.md](./ROADMAP.md).

## Tech stack

Versions are the ranges in `package.json`.

| Layer | Choice |
|---|---|
| App | Expo SDK 54 (`expo ~54.0.37`), React Native 0.81.5, React 19.1.0, TypeScript ^5.3 |
| Routing | expo-router ~6.0.24 (file-based, `app/`) |
| Animation / gestures | react-native-reanimated ~4.1.1, react-native-worklets 0.5.1, react-native-gesture-handler ~2.28 |
| Backend | Supabase (`@supabase/supabase-js ^2.106`): Postgres + RLS, Auth, Storage, Edge Functions (Deno) |
| LLM | Google Gemini via `supabase/functions/_shared/llm/` (Flash-Lite primary, failover to other Gemini models; Groq only when `LLM_FALLBACK=groq`) |
| Cutout | On-device Apple Vision, in the local Expo module `modules/subject-cutout`; server-side Replicate rembg / remove.bg only as a fallback in `create-sticker` |
| Analytics | Aptabase (`@aptabase/react-native`) |
| Builds | EAS Build, dev client (`expo-dev-client`); the `ios/` folder is generated by prebuild and gitignored |
| Tests | Node's built-in test runner on `.mts` scripts, `tsc`, `deno check`, Maestro UI flows |

This is Expo SDK 54. Check <https://docs.expo.dev/versions/v54.0.0/> before
assuming an API's shape (see `AGENTS.md`).

## Local setup

Requirements: Node, Xcode with an iOS Simulator (or a physical iPhone), and an
EAS account for the dev client build.

```bash
npm install
```

### Environment variables

Two gitignored files in the repo root: `.env` (the **staging** project; what
Metro and every script use) and `.env.production` (production; scripts use it
only with `TABI_ENV=production`). `npx eas-cli env:pull --environment development`
recreates `.env`. The app reads only these names, all inlined at bundle time:

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY`
- `EXPO_PUBLIC_APTABASE_APP_KEY` (production only; analytics stay off elsewhere)

Cloud builds get the same names from EAS environment variables
(`development`/`preview` = staging, `production` = production).

Edge functions read these secrets (set with `npx supabase secrets set`, never
committed): `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
(provided by the platform), `GEMINI_API_KEY`, and optional tuning
`GEMINI_MODEL`, `GEMINI_FALLBACK_MODELS`, `GEMINI_MEDIA_RESOLUTION`,
`GEMINI_THINKING_BUDGET`, `LLM_FALLBACK`, `GROQ_API_KEY`, `GROQ_MODEL`,
`DAILY_LIMIT_OVERRIDES`, and for the server cutout fallback `REPLICATE_API_TOKEN`,
`REPLICATE_MODEL`, `REPLICATE_VERSION`, `REPLICATE_WAIT_SECONDS`,
`REPLICATE_ALPHA_MATTING`, `REPLICATE_ALPHA_MATTING_FG_THRESHOLD`,
`REPLICATE_ALPHA_MATTING_BG_THRESHOLD`, `REPLICATE_ALPHA_MATTING_ERODE_SIZE`,
`REMOVEBG_API_KEY`.

Scripts: `scripts/test-gemini-live.mts` and `scripts/prompt-lab.mts` read
`GEMINI_API_KEY` (the latter also from a gitignored `.env.gemini`);
`scripts/test-gemini-live.mts` also reads `LIVE_LANGS`. These call the paid
Gemini API.

### Run the dev client

The app uses custom native code, so Expo Go does not work. Build the dev client
(Tabi Dev) once (see EAS below), install it, then:

```bash
npm run dev      # APP_VARIANT=development, file watching on, staging backend
```

JS/TS changes hot reload through Metro; no new build is needed. A phone connects
over the LAN (default `--host lan`), not tunnel. A Metro started with `CI` set
never re-bundles; `npm run dev` unsets it (this is what the QA tooling expects).

| Script | Does |
|---|---|
| `npm run dev` | Metro for the Tabi Dev client (`APP_VARIANT=development`, file watching on) |
| `npm start` / `ios` / `android` / `web` | `expo start` (with `--ios`, `--android`, `--web`). Only iOS is exercised. |
| `npm run deploy -- <staging\|production> <db\|functions\|all>` | `scripts/deploy.sh`; see `RELEASING.md` |
| `npm run lint` | `expo lint` |

| `npm run typecheck:functions` | `deno check` over every edge function and `_shared` module (needs Deno installed) |
| `npm test` | Node test runner over `scripts/test-sentence-logic.mts`, `test-llm.mts`, `test-any-word.mts`, `test-review.mts` (offline) |
| `npm run test:llm` | Just `scripts/test-llm.mts` |
| `npm run test:live` | `scripts/test-gemini-live.mts` against the real Gemini API (needs `GEMINI_API_KEY`; costs money) |
| `npm run prompt` | Prints the rendered sentence prompt (`scripts/show-prompt.mts`) |

## Testing

1. Static and unit: `npm run typecheck && npm run lint && npm test && npm run typecheck:functions`.
   `harness/init.sh` runs this gate.
2. UI: Maestro on the iOS Simulator through `harness/qa.sh` (one flow:
   `harness/qa.sh .maestro/agent/<flow>.yaml`; no argument runs every flow).
   It checks the Simulator, the installed dev build and that Metro is serving
   this tree, then prints a short pass/fail summary and writes
   `harness/logs/qa-status.json`. It runs against staging with `.maestro/qa.env`
   (create the QA account once with `.maestro/create-qa-user.sh`). The QA account has a budget
   of 100 AI calls per UTC day per project; check `node scripts/qa-budget.mjs` first. New
   flows go in `.maestro/agent/`; do not edit the human-approved `.maestro/*.yaml`.
3. Unattended loop: `harness/run-loop.sh` (see `harness/README.md`).

## Deploying and releasing

All of it is in [RELEASING.md](./RELEASING.md): the environments, backend
deploys (`scripts/deploy.sh staging …` first, production only from a pushed
`main` commit that ran on staging), App Store releases through TestFlight with
phased release, and over-the-air updates.

**EAS builds are rationed** (15 iOS builds/month on the free plan, tracked by
the owner): **do not run `eas build`, `eas submit` or `eas update` without
asking first.** Profiles in `eas.json`: `development` (Tabi Dev),
`preview` (Tabi Preview), `production` (Tabi Stickers, store submit config).
Only rebuild for native changes; everything else hot reloads.
